## Qué cambia

Respecto a lo que pueda haber en cada tenant (lo de las dos últimas semanas, lo que más
probablemente falte):

- Registro de despliegues: cada script anota en `state/despliegues.jsonl` del tenant lo que
  aplica. Lo pinta `scripts/aegora-estado.sh`.
- `deploy-booking.sh` sin `--ref` despliega el `BOOKING_REF` de `release.env`, no `main`.
- `apply-schema` conserva los displays de nuestras extensiones; el gestor deja de configurar
  servicios, recursos, ubicaciones y calendarios (`bf3685e`).
- WhatsApp: Lucía calla 10 min cuando contestan desde el móvil y retoma lo que quedó sin
  contestar (`dd28b05`, `489d346`).
- Importar una agenda de contactos (`5d1b6a5`, `1c9c0f4`, `8ae56ca`).
- Aviso al equipo por tarea, recordatorio de la víspera, correo por reserva, escribir por
  WhatsApp a un contacto con plantilla (11-16/nov).
- Maquetas de webchat `/alcazar` y `/jca` (sirven desde el checkout, no van por tenant).

## Pasos (VPS) — hasta que exista `actualizar-tenant.sh`

`T` = el tenant. Cada script, primero sin `--apply` (PLAN), se revisa, y luego con él.

```bash
cd /opt/aegora/platform && git fetch origin --tags && git checkout v2026.11.26
```

```bash
T=dev
sudo ./provisioning/tenant/render-tenant-config.sh --tenant $T
sudo ./directus/configure-directus-extensions.sh --tenant $T
sudo ./directus/apply-schema.sh --tenant $T
```

Con los tres PLAN revisados:

```bash
T=dev
sudo ./provisioning/tenant/render-tenant-config.sh --tenant $T --apply
sudo ./directus/configure-directus-extensions.sh --tenant $T --apply
sudo ./directus/apply-schema.sh --tenant $T --apply
sudo bash -c "source scripts/lib/esperar-contenedor.sh && reiniciar_y_esperar ${T}-directus"
for s in views ui presets; do sudo ./directus/configure-directus-$s.sh --tenant $T --apply; done
sudo ./directus/configure-spanish-ui.sh --tenant $T --apply
sudo ./directus/configure-tenant-role.sh --tenant $T --apply
sudo ./directus/configure-n8n-service.sh --tenant $T --apply
sudo ./directus/configure-directus-insights.sh --tenant $T --apply
sudo bash -c "source scripts/lib/esperar-contenedor.sh && reiniciar_y_esperar ${T}-directus"
```

Si `render-tenant-config` dijo que hay que recrear contenedores, se recrean antes de seguir
(`docker compose up -d --force-recreate` en la carpeta que indique, nunca `restart`).

```bash
T=dev
sudo ./provisioning/tenant/deploy-booking.sh --tenant $T
sudo ./n8n/render-workflows.sh --tenant $T
```

Revisado el PLAN (línea de secretos de WhatsApp y Retell incluida):

```bash

sudo ./n8n/render-workflows.sh --tenant $T --apply
```

`whatsapp-templates` solo con `--apply` si dice que falta alguna. Al acabar:


y el tenant tiene que salir con `v2026.11.26` en todas las columnas. Luego, de vuelta:
